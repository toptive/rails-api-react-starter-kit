# Internationalization

## Three layers

`i18n/translations.csv` is the release source: the header lists supported locales in order,
with English first. `pnpm i18n:build` (or `bin/rails i18n:build`) generates flat JSON under
`i18n/locales/` and nested Rails YAML under `config/locales/`. Never edit generated files.
The translation gate validates unique keys, filled release cells and staged generated output.

The `translations` table stores `(key, locale, value, edited)` with a unique key/locale index.
CSV keys and database-only keys both appear in the admin editor. Editor values are raw cells,
including empty strings, so its missing-locale filter can identify untranslated text.

`TranslationCatalog` memoizes one flat map per locale in each process. Release cells supply
defaults, with empty release cells falling back to English. Database rows overlay the map when
edited or nonempty. An edited empty string is an intentional override and stays empty.
`I18n.t` and the public locale endpoint read this same catalogue. Rails converts `{{name}}`
placeholders to `%{name}` at lookup; public JSON retains the original placeholder syntax.
Framework translations absent from the catalogue continue to use Rails' normal backend.

## Deploy synchronization

```sh
bin/rails i18n:sync
```

The Docker entrypoint runs `db:prepare`, then `i18n:sync`, before starting the server.
Synchronization inserts missing CSV cells; refreshes unedited rows when the CSV supplies a
changed nonempty value; deletes unedited rows whose key left the CSV; and preserves every
edited row, including edited empty cells and keys removed from the release. Repeating a sync
without content changes preserves the catalogue version. Sync, edits and fill persistence
share a PostgreSQL transaction advisory lock to avoid overwriting one another.

## Runtime editor and AI fills

Superadmins use `GET /api/v1/admin/translations?q=&missing=&page=&perPage=`. Search matches
keys or raw values case insensitively. Results sort by key and include all supported locales in
CSV order. `PUT /api/v1/admin/translations/:key` accepts flat `locale` and `value` fields; URL
encode the key and leave dots intact. Values may be empty and have a 20,000-character cap.
Updates mark the cell edited and record `translation.updated`.

`POST /api/v1/admin/translation-fills` accepts a non-default `locale`. `Ai` calls OpenRouter
in batches of 40 keys, preserving placeholders. Set `OPENROUTER_API_KEY` through `cred` and
optionally `OPENROUTER_MODEL` (default `openai/gpt-4o-mini`). Missing credentials return
`503 ai_not_configured`; provider errors or invalid output return `503 ai_unavailable` without
partial database writes. Filled cells are edited and audited. A manual edit while the provider
is answering wins. The synchronous response is `{ count }`; large products can move this
model operation into a declared queue.

After committed edits, an ActiveSupport notification invalidates the local memo. A Solid
Cable broadcast on the internal `runtime_i18n` topic delivers the same notification to other
processes; no public channel or browser subscription is exposed. Sync also invalidates and
broadcasts. Each process subscribes when it first loads a database-backed catalogue.

## Delivery and locale selection

`GET /api/v1/locales/:locale` returns a flat map, `meta.locale` and `meta.version`. The version
is a deterministic SHA-256 hash of the sorted effective catalogue content. Bootstrap exposes
that same `i18nVersion`. Content changes invalidate every locale ETag; no-op syncs keep it.
The response uses `ETag: "<locale>:<version>"` and `Cache-Control: public, no-cache`; matching
`If-None-Match` returns an empty 304. Unsupported locale resources return 404.

Requests select supported `?locale=` first, then weighted `Accept-Language`, the signed-in
user's locale and English. Region tags fall back to their base language. Every action runs
inside `I18n.with_locale`; rescued errors explicitly resolve the same locale. Emails use the
recipient's locale. React uses `t("namespace.key")`; Rails uses `I18n.t`. Validation details
carry CSV keys, translated messages and optional bindings.

Add a locale column to the CSV, fill its cells, rebuild and stage the generated catalogues.
Rails' available locales and default come from the CSV header. Deployment sync creates its
runtime rows without changing previous edits.
